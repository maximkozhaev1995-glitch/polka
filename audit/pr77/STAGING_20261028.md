## Что исправлено

1. Быстрый и подтверждённый пакетный перенос на стойку больше не удаляет
   `stop/stopAuto`. Пополнение, перенос, наличие на стойке и снятие стопа —
   отдельные действия. Явное снятие стопа и вывод позиции из палитры сохранены.
2. Крепость и граммовка сохраняются в `flavor_strengths` / `flavor_packs` с
   ключом `(venue_id,flavor_id)`. Общий каталог остаётся источником значений
   по умолчанию. Одинарное и пакетное изменение создаёт локальные overrides;
   очистка граммовки сохраняет null override, удаление override возвращает
   общее значение. Ошибка чтения overrides не маскируется успешной загрузкой.
3. Сотрудникам запрещена запись в общий каталог, а также чтение/изменение
   частных вкусов другого заведения. Свои custom-вкусы остаются редактируемыми.
   Restrictive RLS-ограничения защищают и от оставшихся permissive-политик.
4. Гостевая карта учитывает локальную крепость выбранного заведения.
   Публично читается только крепость общих вкусов; приватные вкусы и граммовка
   гостям не открыты. Общие значения и прежний встроенный снимок сохранены.
5. Проверка JWT в AI принимает необязательный серверный параметр секрета для
   тестирования. Рабочий HTTP-handler его не передаёт и использует прежний
   `APP_JWT_SECRET`. Секрет из HTTP-параметров не принимается.

«Неликвид», его пять алгоритмов, действия и дополнительное меню не менялись.
Пять основных разделов сохранены. Выбранный складской протокол — `apply_stock`
из #74; альтернативный `commitStockBatch` из #75 не добавлялся.

## Advisors и оставшиеся ограничения

Security advisors: нет нового mutable-search-path предупреждения; остаются
публично вызываемые SECURITY DEFINER `me_venue`, `me_role`, `is_staff` для
guest/RLS-зависимостей. Для гостя они возвращают null/false, полномочия
берутся из проверенного identity и актуальной users. Это явно просмотренная
граница, а не заявление «advisors полностью зелёные». Закрытая таблица receipts
имеет RLS без клиентских политик намеренно.

Performance advisors: два FK новых таблиц покрыты индексами; на пустых таблицах
они отмечены как пока не использованные. Остаются шесть прежних FK без индексов
и предупреждения о нескольких permissive-политиках baseline. Оптимизация всей
исторической схемы не входит в это исправление.

Не выполнены в этом прогоне: полноценный browser/WebView flow сотрудника с
настоящим Telegram, полный `ai` / `tg-auth` deployment с секретами на стенде,
Storage HTTP с файлами и полным baseline, настоящий OCR исходных фотографий,
повтор многосессионных/браузерных гонок для окончательной схемы. Старые локальные
browser/concurrency результаты из RESULTS.md не выдаются за новый live-прогон.
Остаются ограничения восстановления разных намерений через общее localStorage,
отдельных транзакций заказов/каталога/inv_log и исторической отмены из #74.

## До выпуска и откат

PR остаётся Draft. Резервная копия production и пробное восстановление всё ещё
не подтверждены; этот тестовый прогон не заменяет backup. Merge/deploy в
production этим изменением не выполнялись и не разрешаются автоматически.

Клиент, гостевая карта и миграции должны выпускаться согласованно. Старый клиент
продолжает пытаться менять общий каталог; после новых RLS такие операции будут
отклоняться. Откат только клиентской страницы без рассмотрения схемы небезопасен.
При откате не удалять таблицы overrides и не переносить их значения обратно в
общий каталог: это может потерять локальные настройки или затронуть другие
заведения. Для рабочего выпуска сначала нужны проверенный backup, baseline,
испытания полного employee flow и согласованный совместимый rollback.
