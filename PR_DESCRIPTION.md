# MIXORA stage 1: устранить ложные совпадения и предложить подтверждение действий ИИ

**Draft — не сливать: остаются блокирующие ограничения.**

Kraken Raspberry без линейки больше не превращается в две складские позиции, BARVYORANGE не выбирает Sebero Orange, строки списков обрабатываются независимо. Использованы и проверены существующие исправления ветки claude/project-thread-lt6454, без merge ветки.

Главный и секционный помощники формируют предложения заказа и меток вместо немедленных записей. /заказать и заказная часть /списать и заказать требуют подтверждения. Проза модели не запускает orderFixBox/stockFixBox. Ошибка/остановка модели отбрасывает ещё не принятые предложения. Фото-перенос остаётся в проверяемом складском черновике.

Проверки: 27/27 сценариев matching; 1 144 проверки каталога; 20/20 регрессий действий с UI/API заглушками; сборка приложения; node --check всех inline scripts; git diff --check.

Не выполнены: браузерные прогоны (порт стенда запрещён, Chromium отсутствует), реальный Claude API (ключи не предоставлены), интеграция с тестовой Supabase. **Дополнительное тестирование через настоящий Claude API обязательно.** Рабочая Supabase и Edge Functions не изменялись, деплоя не было.

Блокирующие риски: существующее подтверждение склада записывает stock/moves отдельными запросами и не обеспечивает атомарности/идемпотентности; смешанные orders+stock предложения безопасно отклоняются; складская и заказная части комбинированной команды подтверждаются отдельно. Нужен согласованный транзакционный серверный RPC в последующем изменении. Подробности и таблица до/после: MIXORA_STAGE1_RESULTS.md.
